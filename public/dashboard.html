FAQ

              
Common questions about credits, verdicts, integration, and security.

            

            

              Full FAQ →
            

          


          

            

              

                
                

                  
The fast path (read-only commands like ls, cat, grep) costs 1 credit. Anything that hits the full engine — risky writes, ambiguous intent, pipelines — costs 5 credits. Every /v1/check response returns the exact cost in credits_consumed.

                

              

              

                
                
WARN means a suspicious trajectory the engine is not certain about — human review is recommended. BLOCK means the simulation crossed into Basin B (irreversible damage, exfiltration, compromise) and cannot run.

              

              

                
                
Only WARN can be overridden — from the Playground or the Pending Review widget. Overrides are logged as fresh chain links so the audit trail stays clean. BLOCK is terminal.

              

              

                
                
Wrap every system-level action in a call to POST /v1/check. If ALLOW, run it. If WARN, escalate. If BLOCK, abort. See the integration docs for full details.

              

              

                
                
Fast path returns in under 1 ms. Full engine runs in 50–500 ms. Read-heavy agents typically see ~95% fast-path hit rate, so the average overhead is negligible.

              

              

                
                
Each verdict is hashed with SHA-256 over the decision payload (command, intent, verdict, timestamp, evidence). The hash chain-links into a tamper-evident audit log — if any entry is altered, the chain breaks.

              

              

                
                
The API returns HTTP 402 on every subsequent /v1/check. Agents pause, surface the error, and wait for a top-up. No silent bypasses.

              

              

                
                
Commands and intents are evaluated in-memory and hashed. Only cryptographic proof hashes and basic audit metadata (credits, timestamps, verdicts) are persisted. Self-hosted deployments are available for regulated buyers.

              

              

                
                
Yes — contact Reality Kernel support. The old key is invalidated immediately, and the new key inherits your existing credit balance and history.
