# Design note: Phase 0 (build system and truthful CI) and Phase 1 (shared ABI)

Status: **ACCEPTED** (2026-10-19). Implementation differs from this note in four
places, each recorded as an ADR:
- bindings are generated at build time instead of committed and diffed
  ([ADR-0004](../decisions/0004-abi-bindings-at-build-time.md));
- `vmlinux.h` is vendored from libbpf/vmlinux.h instead of generated on runners
  (ADR-0004);
- the VM matrix uses vmtest with pinned LVH kernels, because the LVH action
  cannot pass `lsm=...,bpf` ([ADR-0003](../decisions/0003-kernel-matrix-vmtest-lvh.md));
- there is no `SEC("syscall")` ABI program, because aya 0.13 cannot load that
  program type. The end-to-end ABI check uses records emitted by the
  `rk_test_*` programs instead, and feature probes moved to `rk_probes.bpf.o`.
Branch: `phase-0-1-foundations`
Plan reference: RealityKernel_Engineering_Plan.pdf, Phases 0 and 1 (baseline 6975fbd)

## 0. Context

This branch already holds a first attempt at both phases (commit 913c1d7). CI run 39283302062 on
0f01bfa fails in three places, all for real reasons:

| Job | Failing step | Root cause |
|---|---|---|
| Code Hygiene | `cargo fmt --check` | Unformatted Rust. Clippy and deny never run. |
| Cross-Compile BPF | `make` | `BPF_PROG` used without `<bpf/bpf_tracing.h>`. Host `<linux/types.h>` and no `vmlinux.h`, so it is not CO-RE. |
| Decoder Fuzz | `cargo fuzz run` | `rk_sensor::decoder` is not exported (the lib is a marker fn). `fuzz/` is neither excluded nor its own workspace. |
| VM Kernel Matrix | (skipped) | Would pass anyway: it boots no VM and ends in `\|\| true`. |
| ci.yml `cargo check` | (not run on this branch) | `rk-sensor/src/event.rs` imports types removed from `rk-ebpf-common`. |

This note describes how to make both phases pass the plan's acceptance criteria in CI. All
verification happens on free GitHub-hosted runners because no local toolchain is available (§5).

## 1. Repository and workspace changes

1. Add to the root `Cargo.toml`: `exclude = ["fuzz"]`. Delete `rk-ebpf-probes/`. It does not compile
   against the locked aya-ebpf, nothing depends on it, it stays in git history, and the plan
   replaces it with `rk-bpf/*.bpf.c` (recorded in ADR-0002).
2. Delete `rk-sensor/src/event.rs` and `rk-sensor/src/enricher.rs`. They depend on the old ABI. The
   plan replaces /proc enrichment with a process table in Phase 7.
3. Delete `rk-sensor/src/dev_stub.bpf.o`. It is a 136-byte text file that pretends to be an ELF.
4. Split `rk-sensor` into a library (`decoder`, `loader`, `selftest`, `consumer`, `pipeline`) and a
   thin `main.rs`, so tests and the fuzz target can use the decoder.
5. Move Python tests out of the kernel workflow and keep them in `ci.yml`.

## 2. Phase 0: build

### 2.1 BPF build (`rk-bpf/`)
- **`vmlinux.h`.** Vendor per-arch headers at `rk-bpf/include/vmlinux/{x86,arm64}/vmlinux.h`. They are
  generated by an `xtask gen-vmlinux` job with `bpftool btf dump file /sys/kernel/btf/vmlinux format c`
  on a native x86_64 runner (`ubuntu-24.04`) and a native arm64 runner (`ubuntu-24.04-arm`, free for
  public repos). Each header records the kernel version it came from in a comment. CO-RE relocations
  make one header valid across the whole matrix.
- **Makefile.** `-g -O2 -target bpf -Wall -Werror -D__TARGET_ARCH_$(ARCH) -Iinclude/vmlinux/$(ARCH)`.
  Include `vmlinux.h`, `bpf_helpers.h`, `bpf_tracing.h` and `bpf_core_read.h`. `rk_abi.h` keeps its
  `__VMLINUX_H__` guard so the same header serves the BPF side and the bindgen side. `llvm-strip -g`
  stays, but the BTF sections are kept (aya needs `.BTF` and `.BTF.ext` for CO-RE).
- **Licence.** Each object declares `SEC("license") = "Dual MIT/GPL"`, matching the plan's dual
  GPL-2.0/MIT. Update the SPDX headers to `(GPL-2.0-only OR MIT)`.
- **Objects:**
  - `rk_selftest.bpf.o` (renamed from `minimal.bpf.c`): LSM counter, connect4 test hook, ring buffer
    round trip. Only `--selftest` loads it.
  - `rk_events.bpf.o`: shared helpers and maps. In Phase 0/1 it holds only a `SEC("syscall")` program
    (`rk_abi_selftest`) that the selftest runs with `BPF_PROG_TEST_RUN` (§3.4). Phases 2 to 4 add the
    real hooks to this object.
  - `reject_infinite_loop.bpf.o`: negative control. It is not embedded in the sensor.

### 2.2 Embedding, with no runtime path override
- `rk-sensor/build.rs` uses `include_bytes_aligned!` on `$RK_BPF_OUT_DIR/{rk_events,rk_selftest}_$(arch).o`
  when the `embedded-bpf` feature is on.
- Without the feature, `loader` returns `Err(NotEmbedded)` with a clear message instead of parsing a
  fake object.
- `#[cfg(all(not(debug_assertions), not(feature = "embedded-bpf")))] compile_error!(...)` makes a release
  build without embedded objects fail to compile. That is the acceptance criterion
  "no runtime override for the BPF object path". No env var or CLI flag accepts a path, and a test
  greps the binary's CLI help to confirm it.

### 2.3 Daemon behaviour in Phase 0/1
The current `main` attaches the test connect4 program to the **root cgroup**, which blocks
192.0.2.1 for the whole host. After this change, the daemon loads `rk_events.bpf.o`, attaches nothing
that can deny (no enforcing hooks exist until Phase 2), drains `events_ringbuf`, and logs. Only
`--selftest` ever attaches the test programs, and only to a temporary child cgroup that it deletes
afterwards.

### 2.4 `rk-sensor --selftest`
- **Loads every program in every embedded object** and reports `{name, type, loaded, attached, error}`
  for each one. A verifier rejection of any program means exit code 1. This satisfies "a PR that
  introduces a verifier-rejected program turns CI red".
- **Capability report** (JSON): kernel release, arch, `bpf_lsm_active` (from `/sys/kernel/security/lsm`),
  `btf_present`, `ringbuf_supported`, `cgroup_v2`, effective capabilities, per-hook attach results, and
  `enforcement_available`.
- **Functional checks** (kept from the current version, which is well designed): LSM counter
  increment, connect4 EPERM in a temporary cgroup via a re-exec'd child, and the ring buffer round trip.
  The round trip changes: it now emits a real `RK_EV_NET_CONNECT` record through the shared helpers, and
  the selftest decodes it with the production decoder and checks its fields (§3.4).
- **Exit codes:** 0 means all checks passed. 1 means a program failed to load or attach, or a
  functional check failed. 2 means a kernel feature is missing; this is reported loudly and is honest
  degradation, not a pass.

## 3. Phase 1: ABI

### 3.1 Header (`rk_abi.h`)
The existing header already matches the plan: a 48-byte `rk_hdr`, the verdict enum, a variable string
tail with explicit lengths, no 256-byte arrays, and static asserts. Changes:
- Add `RK_ABI_MAGIC`? **No.** `abi` plus `type` plus the exact-length check is enough, and a magic
  number would waste bytes on every event.
- **Verifier-safe scratch.** The BPF-side map value becomes
  `struct rk_scratch_buf { struct rk_scratch_msg msg; __u8 slack[RK_SCRATCH_PAYLOAD_MAX]; }`, so
  `payload[off & MASK]` with a copy length of `len & MASK` always stays inside the map value. The wire
  format (`hdr + 8 + payload_len`) does not change. Today `append_scratch_str` would be rejected
  the first time a program calls it. Nothing calls it yet, which is the only reason CI doesn't show this.
- Document the string-tail encoding (`[__u16 len][bytes]`, `str_count` entries, no NUL) in
  `docs/abi.md`.

### 3.2 Bindings generated from the header
- **Generate, then diff.** `xtask gen-bindings` runs the `bindgen` crate (libclang is preinstalled on
  runners) over `rk_abi.h` and writes `rk-ebpf-common/src/bindings.rs`. `xtask check-bindgen-drift`
  regenerates into a temp file and **diffs byte for byte**. Any difference fails CI and the diff is
  printed. This replaces today's search for struct names.
- **Enums as constants.** Enums are generated as constified modules (`rk_event_type::RK_EV_EXEC: u16`),
  not Rust enums, so a hostile byte from the kernel can never become an invalid enum value.
- **No padding, enforced by the compiler.** A bindgen `ParseCallbacks::add_derives` adds
  `#[derive(bytemuck::Pod, bytemuck::Zeroable)]` to every struct. `derive(Pod)` **refuses to compile any
  struct with implicit padding**, which proves the acceptance criterion "no POD struct contains
  implicit padding" at build time.
- **Layout checks on both arches.** Bindgen's own size and offset assertions, plus the existing
  `const _: ()` block, run in `cargo test` on `ubuntu-24.04` (x86_64) and natively on
  `ubuntu-24.04-arm` (arm64). This covers "layout assertions pass on x86_64 and arm64".

### 3.3 Decoder (`rk_sensor::decoder`)
- **No `unsafe`.** Use `bytemuck::pod_read_unaligned` instead of `ptr::read_unaligned`, and remove
  `unreachable!()`.
- **New API:** `decode(&[u8]) -> Result<Event<'_>, DecodeError>`. Strings come back as a validating
  iterator, which replaces the awkward `&'a mut [&'a str]` out-buffer.
- **Strict checks:**
  - Reject `str_count` larger than what the tail holds. Today the count is silently capped.
  - Reject trailing bytes after the last string.
  - Reject a truncated or malformed FILE path. Today it silently becomes `""`.
  - Reject `verdict` values outside the enum.
  - Reject unknown `type` values.
- **Lossy UTF-8.** Paths and argv are not guaranteed to be UTF-8 on Linux, so they are kept as
  `&[u8]` and shown with lossy conversion. Rejecting them as `InvalidUtf8` would let an agent hide an
  event by naming a file with invalid bytes.
- **Error counters.** A `DecodeStats` struct holds one `AtomicU64` per `DecodeError` variant. It is
  exported later as Prometheus metrics (Phase 9).
- **Tests:** unit tests for every error variant, a Rust test encoder that mirrors the BPF layout for
  round-trip tests, and `proptest` round trips.
- **Fuzzing:** `fuzz/` becomes its own workspace (`[workspace]` table) that depends on `rk-sensor`'s
  library. CI runs `decoder_fuzz` for 10 minutes. The fuzz job also asserts that every input either
  decodes or returns a typed error, with no panic and no counter overflow.

### 3.4 End-to-end ABI proof inside the VM
`rk_events.bpf.o` contains `SEC("syscall") rk_abi_selftest`. When the selftest runs it with
`BPF_PROG_TEST_RUN`, it builds a reference record of each event type using the **production**
helpers (`get_scratch`, `append_str`, `emit`) and sends it to `events_ringbuf`. The selftest drains
the ring buffer, decodes each record with the production decoder, and compares fields against
known values. Running this on every kernel in the matrix proves that kernel layout, helper encoding
and userspace decoding agree.

## 4. CI design (`.github/workflows/kernel.yml` and `ci.yml`)

Every job runs on **free GitHub-hosted runners**, which are unlimited for public repos. They pin
`ubuntu-24.04` / `ubuntu-24.04-arm`, because `ubuntu-latest` moves to Ubuntu 26 starting today.

| Job | Runner | What it gates |
|---|---|---|
| `lint` | 24.04 | `cargo fmt --check`, `clippy --workspace --all-targets -D warnings`, `cargo deny check`, `cargo audit` |
| `test` (matrix x86_64, arm64) | 24.04 / 24.04-arm | `cargo test --workspace`, so layout assertions run natively on both arches |
| `abi-drift` | 24.04 | `xtask check-bindgen-drift` (exact diff) |
| `bpf-build` (matrix x86, arm64) | native per arch | `make -C rk-bpf` with `-Werror`. Uploads objects. |
| `sensor-build` (matrix) | native per arch | `cargo build --release --features embedded-bpf --target <arch>-unknown-linux-musl` (static, so it runs inside any VM image) |
| `verifier-matrix` (5.15, 6.1, 6.6, 6.12, latest stable) | 24.04 + KVM | Boots each kernel with `lsm=...,bpf` using **cilium/little-vm-helper** and runs `rk-sensor --selftest` as root. **Fails on a non-zero exit.** Uploads `selftest-<kernel>.json`. No `\|\| true` anywhere. |
| `negative-control` (inside the same VMs) | 24.04 + KVM | `bpftool prog load reject_infinite_loop.o` **must fail and** the log must contain a verifier rejection message (`back-edge`, `infinite loop` or `too complex`). A **positive control** (loading `rk_selftest.o` with bpftool) must succeed, so "bpftool is broken" can never count as a pass. |
| `fuzz` | 24.04 | 10-minute `cargo +nightly fuzz run decoder_fuzz` |

Arm64 verifier runs need arm64 KVM, which hosted arm runners don't provide. Arm64 objects are
**built and layout-checked natively**. Verifier loads for arm64 are tracked as a known gap in
`docs/kernel-matrix.md`, with options (qemu TCG emulation, slow but free, run nightly only).

**Kernel images: the largest risk.** LVH publishes prebuilt kernels (`quay.io/lvh-images/kernel-images`).
The first CI run will report through the selftest whether those images enable `CONFIG_BPF_LSM` and
`CONFIG_DEBUG_INFO_BTF`. If any image lacks them, a cached workflow builds our own minimal kernels
with those options. Kernels are built once and cached, and only rebuilt when the config changes. The
outcome is recorded in ADR-0003 and `docs/kernel-matrix.md`.

## 5. Working without a local toolchain

No compiler is installed locally, so the loop works like this:
1. Edit the code, commit with Windows `git.exe`, push to `phase-0-1-foundations`.
2. **Readable failures without auth.**
   - Read job and step results from the public GitHub API.
   - `dtolnay/rust-toolchain` registers rustc problem matchers, which turn compiler errors into check-run
     annotations, also public.
   - For non-Rust failures (make, clang, bpftool, VM), a final step `if: failure()` posts the last 50
     log lines as `::error::` annotations.
   - Result: the full error text is reachable without a token.
3. **`autofix` workflow** (manual trigger, phase branches only): runs `cargo fmt --all` and
   `xtask gen-bindings` and pushes a `chore: autofix` commit. Formatting and bindings never depend on
   a local toolchain.
4. **Optional:** a fine-grained token with *Actions: read* on this repo gives full raw logs. It is not
   required.

## 6. Acceptance criteria → named tests

| Criterion (plan) | Test |
|---|---|
| P0: verifier-rejected program turns CI red | `verifier-matrix` (selftest exit code) plus `negative-control`. One-off proof: a throwaway commit that adds an unbounded loop to `rk_events` must go red. Its run link is recorded in the PR. |
| P0: selftest report uploaded per kernel | `verifier-matrix` artifact `selftest-<kernel>.json` |
| P0: no runtime override for the BPF path | `compile_error!` gate, plus `sensor::tests::no_object_path_flag` |
| P1: layout assertions on x86_64 and arm64 | `test` matrix (compile-time asserts plus bindgen layout tests) |
| P1: fuzz 10 minutes without a crash | `fuzz` job |
| P1: no implicit padding in POD structs | `derive(Pod)` on all generated structs (compile failure otherwise), plus `abi-drift` |
| P1: decoder never panics, counts malformed records | `decoder::tests::*` (one per `DecodeError`), `proptest` round trip, fuzz |
| (added) kernel layout matches the decoder | `selftest::abi_roundtrip` inside every matrix kernel |
